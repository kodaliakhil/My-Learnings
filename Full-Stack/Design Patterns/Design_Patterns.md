# Design Pattern

The key to remembering design patterns is to stop thinking of them as code and start thinking of them as **reusable solution ideas**.

## Simple Definition

A design pattern is:

> A proven, reusable blueprint for solving a recurring software design problem.

Notice the important words:

* **Proven** → many developers have used it successfully.
* **Reusable** → works in many projects.
* **Blueprint** → not actual code.
* **Recurring problem** → a problem that appears again and again.

## Design Pattern vs Algorithm

This distinction is extremely important.

#### Algorithm

An algorithm tells you:

> "Follow these exact steps."

**Example**:

Recipe for tea:

1. Boil water.
2. Add tea leaves.
3. Add milk.
4. Serve.

The order matters.

---

### Design Pattern

A pattern tells you:

> "Here's a good way to organize things."

**Example**:

Blueprint for a house:

* Bedroom here.
* Kitchen there.
* Bathroom connected here.

It doesn't tell you every hammer strike.

## Memory Shortcut

Remember:

| Concept        | Think Of  |
| -------------- | --------- |
| Algorithm      | Recipe    |
| Design Pattern | Blueprint |

**Recipe = steps**

**Blueprint = structure**

If you remember only this distinction, you'll retain a large part of the concept.

## What Does a Pattern Description Contain?

Most pattern descriptions have four important parts.

1. **Intent**
   Answers:
   What problem does this pattern solve?
   Example thought:
   "Need a standard way to create objects."
2. **Motivation**
   Answers:
   Why do we need this pattern?
   This section explains the pain point and shows how the pattern helps.
   Think of it as:
   Problem Story → Solution Story
3. **Structure**
   Answers:
   What pieces exist and how are they connected?
   Usually represented through:
   classes
   interfaces
   relationships
   Think of it as the actual blueprint drawing.
4. **Code Example**
   Answers:
   What might this look like in code?
   Since patterns are abstract, code examples help developers understand the idea.

## 30-Second Recall Version

Design patterns are reusable blueprints for solving recurring software design problems. They are not ready-made code or algorithms. An algorithm specifies exact steps to achieve a goal, while a pattern provides a higher-level structure that can be implemented differently in different programs. Pattern descriptions typically include the intent, motivation, class structure, and sample code to help developers apply the solution.
